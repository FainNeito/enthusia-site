# Discord community publishing

Publishing a new news or changelog record queues one announcement per kind and slug in the same database batch. Drafts do not queue. Editing or republishing a previously queued slug does not create another announcement; this prevents ordinary edits from reposting. The message contains the title and a link, and Discord mentions are disabled.

The dedicated scheduled worker is disabled by default. Before activation, apply `migrations/community/0002_discord_delivery.sql` to the same COMMUNITY_DB used by Pages, bind that database to `cloudflare/discord-announcements`, configure the encrypted secrets `COMMUNITY_DISCORD_NEWS_WEBHOOK` and `COMMUNITY_DISCORD_CHANGELOG_WEBHOOK` for the existing announcements and changelog channels, then enable `COMMUNITY_DISCORD_ENABLED=true` and deploy through the reviewed Cloudflare process. Do not place webhook URLs in Git, logs, browser-visible code or chat. The page deployment requires the migration first: published news and changelog writes otherwise fail closed.

The worker posts only to Discord HTTPS webhook URLs, requests confirmation and records pending, processing, sent, failed or uncertain. Explicitly rejected or unconfigured delivery can be retried by an authenticated editor. A network failure, missing Discord confirmation or interrupted worker is uncertain because Discord may have accepted the message. The editor warns that retrying uncertain delivery may create a duplicate and requires explicit confirmation. A timed-out claim is never automatically resent. Claims use per-attempt identifiers to prevent late responses from overwriting later attempts. Scheduled worker outages leave posts queued. A separate review and live test are required; no production delivery has been performed by these local tests.

Historical content does not send retroactively until an editor publishes that record again. A queued record that is archived before the worker claims it is held while not published. Revoking and rotating webhooks is a Discord operation and must be reflected in the worker secrets. Delivery is not exactly-once: after a confirmed resend of an uncertain attempt Discord may contain duplicates.

Local verification: `npm test`; `LOCAL_MINIFLARE_PACKAGE=<local miniflare package.json> node tests/discord-d1-local.mjs` exercises queueing and revision conflicts using local D1 emulation, not Cloudflare's remote D1 service. No EARS validator or SPEAR state helper was found in the repository; this document records the requirement, design, and verification boundary.

News-editor posts tagged `Changelog` also use the changelog channel; other news categories use the announcements channel. Changelog records link to the changelog page, while news records link to their selected news post. This routing depends on both webhook secrets being provisioned separately.
